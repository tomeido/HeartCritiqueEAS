# 어떤 날것의 글을 박제해야 하는가 — 아카이브 가치 기준 연구

> 이 문서는 `services/value.py`(아카이브 가치 스코어러)와 collector 캡처 정책의 설계 근거다.
> "삭제될 것 같은 글"(volatility)과 "박제할 가치가 있는 글"(value)은 **다른 축**이다.
> 곧 지워질 글이라도 스팸이면 박제할 이유가 없고, 오래 남을 글이라도 유일한 1차 증언이면
> 원본 사이트 폐쇄·정책 변경에 대비해 박제할 가치가 있다.

## 1. 이론적 배경

### 1.1 셸렌버그(Schellenberg)의 평가론 — 증거가치와 정보가치
전통 기록학의 평가(appraisal) 기준을 커뮤니티 글에 옮기면:

- **증거가치(evidential value)**: 그 글이 "무슨 일이 있었는지"를 증명하는 힘.
  당사자의 1인칭 진술, 첨부된 물증(사진·녹취·영수증·캡처), 구체적 시간·장소·행위 기술.
  → 커뮤니티 글의 증거가치는 *직접 경험 + 물증 언급*에서 나온다.
- **정보가치(informational value)**: 제3자(미래의 연구자·언론·법정)에게 유용한 정보.
  기업 비위의 구체적 수법, 소비자 피해의 재현 조건, 선행의 맥락.
  → 구체성(길이·고유명사·수치)이 대리 지표다.

### 1.2 유일성(uniqueness) — 언론 격차(gap)와 1차 사료성
이미 뉴스로 보도된 사건의 커뮤니티 반응글은 유일성이 낮다(뉴스가 아카이브를 대신함).
반대로 **언론이 다루지 않은 1차 증언**은 그 글이 사라지면 세상에서 사건 자체가 사라진다.
이 프로젝트의 gap 탐지(`community_count` vs `news_count`)가 검색 파이프라인에서 재는 것과
같은 축이며, 캡처 단계에서는 **기사 펌글(뉴스 링크 재게시) 여부**가 가장 싼 대리 신호다.

### 1.3 위험 기반 선별 — Archive Team의 "at-risk" 원칙
웹 아카이빙 실무(Archive Team, IIPC)는 "가치 × 소멸 위험"으로 우선순위를 매긴다.
이 프로젝트에선 소멸 위험은 `volatility.py`(삭제확률)가 담당하므로, value 축은 순수하게
"사라지면 아까운 정도"만 잰다. **캡처 우선순위 = 가치 + 소멸위험의 결합**이다.

### 1.4 윤리적 하한 — Documenting the Now 원칙
소셜/커뮤니티 아카이빙 윤리(DocNow)의 핵심: **당사자가 지운 것을 박제하는 행위는
공익이 사생활 침해를 능가할 때만 정당하다.** 이 프로젝트의 기존 안전장치(PII 게이트,
LLM 익명 재작성, raw 본문 비공개, critique 수동 검토)가 이 하한이다. value 스코어러는
공익성이 낮고 사적 노출만 있는 글(연애 상담, 신변 잡담)을 *가치 낮음*으로 분류해
캡처 우선순위에서 밀어냄으로써 윤리 하한을 선별 단계에서도 한 번 더 지킨다.

## 2. 박제 가치가 높은 글 (가산 신호)

| 신호 | 왜 가치인가 | 탐지 방법 |
|---|---|---|
| **1인칭 직접 경험** ("제가 겪은", "당사자입니다", "재직 중인") | 1차 사료. 전문(傳聞)이 아닌 증언 | 1인칭+경험 동사 패턴 |
| **물증 언급** (사진·영수증·녹취·진단서·계약서·캡처 첨부) | 증거가치의 핵심. 물증 있는 폭로가 takedown 1순위이기도 함 | 증거 명사 패턴 |
| **공익 제보** (기업/권력자 실명 + 비위 주장) | 언론 사각지대의 감시 기능 — 미션의 핵심 | `volatility.ACCUSATION_RE`+`ENTITY_RE` 재사용 |
| **내부고발** (재직자/퇴사자의 조직 내부 정보) | 외부에서 재구성 불가능한 유일 정보 | `volatility.WHISTLEBLOWER_RE` 재사용 |
| **소비자 안전** (제품 결함·위생·의료사고 등 피해 재현 정보) | 제3자 피해 예방의 정보가치 | 피해·결함 어휘 패턴 |
| **목격 미담** (구조·선행·헌신의 구체적 목격담) | kindness 카테고리의 존재 이유. 훈훈함이 아니라 '기록되지 않으면 사라질 선행' | 미담+구체 행위 패턴 |
| **구체성** (충분한 본문 길이, 시간·장소·수치) | 정보가치의 대리 지표. 한 줄 글은 재작성해도 내용이 없다 | 본문 길이 계단 |

## 3. 박제 가치가 낮은 글 (감산·제외 신호)

| 신호 | 왜 배제하나 | 처리 |
|---|---|---|
| **광고·홍보·거래** (쿠폰, 할인코드, 공동구매, 팝니다) | 상업 정보. 소멸이 손실이 아님 | **hard negative — 캡처 자체 제외** |
| **단순 질문·잡담** ("~뭐가 좋나요?", "심심하다") | 증거·정보가치 모두 없음 | 감산 |
| **뉴스 기사 펌글** (기사 링크+짧은 코멘트) | 유일성 없음 — 원 기사가 아카이브를 대신 | 감산 |
| **한 줄 글 / 링크 온리** | 재작성할 실체가 없음 (promoter 의 no_fit 사전 차단) | 감산 |
| **사적 신변 노출만 있는 글** (연애·가족 갈등 상담 등 공익 없음) | 윤리 하한 — 공익 없는 사생활은 박제 대상이 아님 | 공익 신호 부재 시 자연히 저점 |

## 4. 적용 지점

1. **캡처 우선순위** (`collector.poll_feeds`): 피드 내 정렬 키를
   `volatility(삭제위험) + value(가치)` 결합 점수로. 예산이 빠듯할 때
   "곧 지워질 && 지워지면 아까운" 글부터 잡는다.
2. **스팸 사전 제외** (`collector`): hard negative(광고·거래)는 본문 GET 예산 자체를
   쓰지 않는다(정중한 폴링 원칙 — 무가치 글에 요청을 낭비하지 않음).
3. **승격 후보 정렬** (`promoter.find_promotable`): hard 삭제 확정 후보가 여럿일 때
   가치 높은 글부터 승격(주기당 배치 상한이 있으므로 순서가 중요).
4. **생성 게이트에는 주입하지 않는다** — volatility 와 동일 원칙. 점수는
   *선별·우선순위·UI 배지* 전용이며, 박제 여부는 여전히 인간 투표 + hard 삭제 신호만
   결정한다(자동화된 가치판단이 영구 박제를 좌우하면 안 됨).

## 5. 점수 설계 (services/value.py)

- 0~10 정수, 결정적(같은 입력 → 같은 출력), 순수 표준 라이브러리.
- 신호 없으면 낮게(보수적 디폴트) — volatility 와 동일 원칙.
- 가중치는 `VALUE_W_*` 환경변수로 튜닝 가능하며, `/api/transparency` 로 실시간 공개된다
  (선별 알고리즘의 투명성 — docs/TRANSPARENCY.md 참고).
- `hard_negative`(광고·거래)는 점수와 별개의 불리언으로 반환해 캡처 제외 게이트에 쓴다.

## 6. 한계와 비고

- 정규식 기반이므로 반어·은어·오타는 놓친다. 점수는 *순위*용이지 *판정*용이 아니다.
- 유일성(언론 격차)은 캡처 시점에 검색 없이 잴 수 없어 "기사 펌글 감산"으로 근사한다.
  승격 이후의 정확한 gap 측정은 기존 검색 파이프라인의 몫.
- 가치 기준 자체가 편향을 가질 수 있다(무엇이 '공익'인가). 그래서 기준을 이 문서와
  transparency API 로 공개하고, 가중치를 env 로 조정 가능하게 열어 둔다.
